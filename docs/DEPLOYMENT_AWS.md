# AWS Deployment Guide

This is the simplest owner-oriented deployment path for the competition build.

## 1. Prerequisites

You need:

- an AWS account;
- access to AWS CloudShell;
- a subscription to the official Cloud Optimized OpenCV (COOL) Marketplace image for AWS Graviton;
- the regional COOL AMI ID;
- this repository ZIP or Git clone.

The deployment script creates the supporting AWS infrastructure with Terraform.

## 2. Choose one AWS region

Use one region for the entire deployment. The selected region must offer the subscribed COOL Marketplace image.

A nearby European region such as `eu-west-1` is a reasonable default when the Marketplace image is available there.

## 3. Obtain the COOL AMI ID

After subscribing to COOL in AWS Marketplace, copy the AMI ID shown for your selected region.

It will look like:

```text
ami-0123456789abcdef0
```

Do not use that example value.

## 4. Open AWS CloudShell

Open CloudShell from the AWS console in the same region.

Upload the project ZIP using **Actions → Upload file**, then run:

```bash
unzip ciberia-visionguard-opencv26.zip
cd ciberia-visionguard-opencv26
```

If the extracted directory has a different name, `cd` into that directory instead.

## 5. Export the real COOL AMI ID

```bash
export COOL_AMI_ID=ami-REPLACE_WITH_YOUR_REAL_AMI
```

Optional overrides:

```bash
export AWS_REGION=eu-west-1
export INSTANCE_TYPE=c8g.xlarge
```

The script can automatically detect a default VPC, subnet and your current public administration IP.

## 6. Deploy

Run:

```bash
bash scripts/aws_quickstart_cloudshell.sh
```

The script will:

1. validate the AWS session;
2. install Terraform when needed;
3. discover networking defaults;
4. create an SSH key pair for this deployment;
5. provision EC2 Graviton, S3, DynamoDB, IAM and CloudWatch support;
6. copy VisionGuard to the instance;
7. configure the COOL runtime;
8. install FastAPI dependencies without replacing COOL's `cv2`;
9. configure the application service and Nginx;
10. verify the health endpoint.

## 7. Verify the application

The script prints the public address. Open:

```text
http://PUBLIC_IP/
```

Then inspect:

```text
http://PUBLIC_IP/api/health
```

For COOL competition evidence, verify that:

- `opencv5_compliant` is `true`;
- the active `cv2` path is under `/opt/cool`;
- the EC2 instance uses Arm/Graviton.

Save a screenshot or raw response under `evidence/screenshots/` or another judge-accessible evidence location.

## 8. Run the two demo scenarios

Upload:

```text
data/demo_clean_intrusion.mp4
```

and then:

```text
data/demo_degraded_intrusion.mp4
```

Expected qualitative behavior:

- clean scenario: uncertain initial evidence can trigger an OpenCV verification tool and then authorize `ACT` when trust gates pass;
- degraded scenario: weak/unstable evidence should lead to `HUMAN_REVIEW` when trust remains inadequate.

Record the resulting traces under `evidence/traces/` for final judging evidence.

## 9. Run the COOL benchmark

SSH into the EC2 instance using the key generated by the quick-start script. From `/opt/visionguard`:

```bash
bash scripts/setup_vanilla_baseline.sh
bash scripts/run_benchmarks.sh
```

This generates:

```text
output/baseline.json
output/cool.json
output/benchmark_comparison.json
```

Copy final versions to:

```text
evidence/benchmarks/
```

Never manually type a performance improvement into the report before the real benchmark has been run.

## 10. Record final environment metadata

Before submission record:

- AWS region;
- EC2 instance type;
- CPU architecture;
- COOL version;
- regional AMI ID;
- OpenCV version;
- active `cv2` path;
- Git commit hash;
- benchmark commands;
- benchmark JSON files.

## 11. Stop the instance when not in use

To reduce spend, stop the EC2 instance from the AWS console when development is paused. A normal public IPv4 address may change after a stop/start cycle.

For the final judge endpoint, use a stable address and HTTPS before publishing it broadly.

## 12. Remove the infrastructure when finished

From the Terraform directory in CloudShell:

```bash
cd deploy/aws/terraform
terraform destroy
```

Review the destruction plan before confirming.

## Important safety notes

- Never commit `.env`, SSH keys, PEM files, AWS credentials or Terraform state.
- Do not expose SSH to `0.0.0.0/0`.
- Keep S3 public access blocked.
- Enable an application API key and HTTPS for a public judge endpoint.
- Do not overwrite the official COOL `cv2` inside `/opt/cool` with `opencv-python`.
